# A1 研究目的与当前系统的差距

当前结论：系统可以承载 A1 的帮助方式比较，也可以作为 A2 的可运行原型展示；它还没有完成 A1 提议的参与者研究，更不能凭软件检查证明学习提升。前一版主要验证功能，对研究流程的支撑不足。

依据是已提交 A1 的 Possible contribution，以及 2026 年 11 月 4 日重新核对的 A2 作业页。A2 允许实现、原型、模拟或已有界面状态的演示；评分看设计推理、已开发交互、技术结构和开发证据。复杂界面和题目数量不能替代这些证据。

## 当前能做什么

| 与研究有关的条件 | 当前实现 | 还不能据此认定什么 |
| --- | --- | --- |
| 比较帮助展示方式 | 先尝试后逐步提示，与立即完整解答；两种模式用同样的已核对步骤 | 没有招募和分组，不能推断哪种更有效 |
| 检查学生自己的工作 | 精确检查一行线性方程是否与原题有相同的唯一解 | 不理解自然语言解释，也不评分概念推理质量 |
| 提供有层次的材料 | 9 道练习及 9 道配对新题，包含负数、分数、括号、两边含 x 和多步骤变形 | 不证明这些题对目标学习者足够难；需要前测和试用 |
| 保持比较的内容边界 | 可在两种条件同时关闭额外的方程反馈；设置会写进记录 | 仍需固定任务顺序并分配条件，不能让正式研究任意挑题 |
| 观察撤去帮助后的表现 | 新题不给出提示或解题步骤，可记录每次有效答案结果 | 当前允许重试且即时反馈，不能直接当受控后测 |
| 留下可审核记录 | 模式、时间戳、请求、显示步骤、检查次数和结果可导出 | 自动演示数据不是参与者数据；会话编号也不是参与者身份 |

## 简单的题会带来什么问题

如果目标大学生在开始前就已经熟练，前测和后测可能都接近满分。即使两种帮助真的不同，也可能观察不到差异。多步骤题缓解了题目单一的问题，但不能保证消除这种天花板风险。

A1 本来研究的是入门代数，因此当前不宜为了显得复杂，直接换成微积分或另一个学科。应先确定对象是需要复习这些技能的学生，并用前测识别其起点；如果多数目标对象已经熟练，应重新调整任务难度和研究范围，而不能挑选性解释结果。

## 将来如何检验 A1 的问题

以下是尚未执行的研究方案，不是当前已开展的实验，也没有参与者结果。

1. 在适当的课程研究安排下，给参与者清楚说明任务、记录内容和退出方式。先做不带帮助的知识检查，确认任务适合目标对象。
2. 预先定义两个条件的分配方式，使用相同任务和经过核对的帮助文本。若研究展示方式，额外的方程反馈要在两组保持同一设置；目前已实现关闭并记录这个设置的能力。
3. 训练阶段记录帮助使用、所用时间和完成情况。正式比较使用预定任务序列，不能把自由练习页面的任意选择直接当作分组实验。
4. 撤去帮助后做未见过的新题。主要正确率应按预先规定的首次有效作答计算，避免重试与即时反馈改变后测；正式后测应把反馈延后。概念解释需要另外的评分标准和人工核对，当前系统没有实现这项评分。
5. 记录感知投入程度；如果保留延迟测试，事先安排时间和材料。分析时报告样本、缺失数据与不确定性。小规模试用可以检查流程是否可行，不能承诺足以证明教学提升；差异不显著也不能写成两种方法等效。

## 本次迭代的判断

新增的方程检查和学习流程，让原型的教学交互更完整；增加多步骤题，回应了材料过于简单的问题。对研究目的更重要的改动，是提供可保持一致的反馈设置，以及明确可用记录和仍缺少的评估环节。

前测、条件分配、固定研究任务序列、无即时反馈的首次作答后测、概念解释评分和参与者招募仍未实现或未执行。当前不应把普通练习流程包装成这些环节已经完成。
